# YOURCALCULATE PROJECT RULES

## Development

- Make the smallest change necessary.
- Inspect before modifying.
- Reuse existing components and utilities.
- Never rewrite working code unnecessarily.
- Never rebuild an existing feature unless explicitly requested.
- Do not modify unrelated files.
- Do not install dependencies unless required.
- Prefer data-driven architecture.
- Avoid duplicate logic.
- Keep the application lightweight and fast.

## Calculations

- All numerical calculations must be deterministic.
- Never use an LLM to calculate numerical results.
- Calculation logic must be independently testable.
- Numerical assumptions and rounding must be explicit.

## SEO

- Calculator functionality is primary.
- Avoid thin programmatic pages.
- Avoid near-duplicate pages.
- Do not generate pages for arbitrary numeric variations.
- Use descriptive URLs.
- Use canonical URLs.
- Build internal links between related calculators.
- Use structured data where appropriate.
- Only create indexable pages when they provide genuine distinct value.

## Education

- Never assume universal grading conversion formulas.
- Store documented grading rules as data.
- Track source, effective date and verification status.
- Distinguish official/exact, standard/recognized and estimated conversions.

## Performance

- Mobile-first.
- Fast.
- Accessible.
- Minimize unnecessary JavaScript.
- Optimize fonts and images.
- Avoid unnecessary animations.
- Prefer server rendering/static generation where appropriate.

## Antigravity workflow

1. Inspect.
2. Plan briefly.
3. Implement requested scope only.
4. Validate.
5. Report.
6. Stop.

Do not proceed to another phase automatically.
